# WorkBuddy（腾讯）：从零讲明白

## 1. 它到底是什么

WorkBuddy 是腾讯做的 **AI 办公工作台**，不是代码编辑器。

你可以把它想成：

- ChatGPT = 会说话的顾问，说完你自己去 Word / Excel 里干活  
- Cursor = 给程序员改代码的编辑器  
- WorkBuddy = **会自己去翻文档、改表格、交作业的同事**，作业一般是 Word、Excel、PPT、PDF，不是 git commit  

官方说法接近「AI 原生桌面智能体工作台」：你用日常说话下任务，它拆步骤、调工具、最后交出能打开的文件。

## 2. 它想解决什么问题

职场人最痛的不是「不会写提示词」，而是：

- 周报、汇总、对表、改 PPT 要在 **微信、邮箱、腾讯文档、本地文件夹** 之间来回跳  
- 普通聊天机器人只给建议，**不交作业**  
- 手机在外面时，还希望家里那台电脑继续干活  

所以产品句是：**听得懂 → 拆得开 → 干得完 → 交得出。**  
交付物是文档和表格，不是「一段建议」。

## 3. 设计概念（公司前台比喻）

把一次「把三份周报合成一页给老板」想成公司办事：

| 概念 | 白话 | WorkBuddy 里是什么 |
|---|---|---|
| 你 | 来办事的人 | 自然语言任务 |
| 前台 | 听懂你要什么、开工单 | 任务拆解 / 规划 |
| 专员 | 各干一摊 | 多个 Agent / 专家 / Skill |
| 档案室 | 公司文件柜 | 资料库（本地文件夹、腾讯文档） |
| 外线电话 | 打给别的系统 | 连接器（邮箱、TAPD、MCP） |
| 工位电脑 | 真的改文件 | 授权目录里的读写、脚本 |
| 成品篮 | 交作业 | 产物：md / docx / xlsx / pptx / 图 |
| 远程遥控 | 出门打电话让同事继续 | 微信 / 企微 / 小程序下指令 |

**Skill（技能）**：一份「怎么干这类活」的说明书 + 工具组合。例如「周报」「对发票」。市场里一键装，相当于给同事发培训手册，而不是每次从零教。

**连接器（Connector）**：插座。插上腾讯文档、QQ 邮箱、自建 MCP，Agent 才能读到那些系统里的东西。资料库原生集成（腾讯文档）和「自定义 MCP 连接器」是两层：前者是产品内置档案室，后者是你自己拉的外线。

**云端沙箱 vs 本机**：小程序「云上模式」在腾讯的临时电脑里干活，不碰你家硬盘；「连接电脑」是遥控你已打开的桌面客户端。这是办公 Agent 和纯 IDE Agent 最大的产品分叉之一。

## 4. 系统拆成哪些积木

从用户看见的，往里剥：

1. **桌面壳**  
   Windows / macOS 客户端：任务列表、对话、产物面板、资料库侧栏。可以同时开多个任务。

2. **任务引擎（还是那口锅）**  
   听任务 → 规划步骤 → 调工具 → 看结果 → 再规划。和 Cursor / Codex 同一口锅，只是工具换成「读 xlsx、写 docx、搜资料库」。

3. **资料库**  
   - 本地：你授权的文件夹  
   - 云端办公：腾讯文档（搜索、引用、回写）  
   任务开始前把文件「添加到任务」，等于把档案从柜子抽到工位上，避免模型两眼一抹黑扫全盘。

4. **Skill 与专家**  
   Skill = 可安装的流程包。专家 = 带人设和工具边界的 Agent（偏 HR、偏数据）。项目空间里可以沉淀「调好的专家 + Skill + 连接器」给同事复用。

5. **连接器 / MCP**  
   内置：文档、邮箱、TAPD、微云一类。自定义：填 MCP Server 地址。Agent 看见的仍是「工具列表」，底层换成 HTTP/MCP。

6. **产物管线**  
   办公格式不是纯文本。最小实现也要有一条路：模型先写 Markdown / CSV，再用库转成 docx/xlsx/pptx。完整产品会直接操作 Office 对象或腾讯文档 API。

7. **远程与计费**  
   IM 把指令打到本机或云沙箱；额度（credits）限制云端模型和长任务。这是商业层，最小自研可以不做。

## 5. 一次任务怎么走（流程）

```
你说：「把本周销售表汇总成一页，发给老板看的 PPT」
    → 程序确认：资料库里哪张表？输出放哪？
    → 拆步骤：读表 → 算汇总 → 生成大纲 → 写成 PPT → 预览
    → 调工具读 xlsx / 腾讯文档
    → 模型根据数字写结构（还可能画图）
    → 写文件到产物区
    → 你打开检查；不行就追问「第三页数字不对」
    → 再进循环改文件
```

停下来的条件：步骤上限、你点停、产物已生成且模型认为完成、某步权限被拒绝。

和写代码的 Agent 一样：**工具失败要把报错原文喂回去**，不要只弹「出错了」。表格公式错了，模型要看见单元格内容才能修。

## 6. 从零开发：按周做，不要第一周对接微信

完整 WorkBuddy 依赖腾讯文档、IM、技能市场、云沙箱，那是大厂产品。你从零能做的是**同思路的最小办公 Agent**。

**第 0 周：只会聊天的办公助手**  
窗口 + 流式对话。系统提示词写：「你是办公助理，交作业时给出 Markdown。」没有工具。你会得到会写周报草稿的记事本。

**第 1 周：ReadFile + 授权目录**  
只允许读用户选中的一个文件夹。模型要先列目录、再读某个 csv/md。这是「档案室」的最小版。**禁止**默认读整个用户主目录。

**第 2 周：WriteFile 到「产物文件夹」**  
所有写入只能落到 `~/WorkBuddyOutbox/`（或你指定的盒子）。界面列出产物，用系统程序打开。人和 Agent 都看得见交了什么作业。

**第 3 周：表格**  
用现成库读 csv/xlsx（Python 的 openpyxl，或 macOS 上你熟悉的任何库）。工具做成：`read_sheet`、`write_sheet`。模型不要直接吐二进制 xlsx。

**第 4 周：一种「真办公格式」**  
Markdown → docx（pandoc 即可）或简单 pptx。先打通一条，不要同时上 Word/Excel/PPT/PDF。

**第 5 周：任务对象**  
数据库或 json 里存：任务标题、状态（跑着 / 等你 / 完成 / 失败）、对话、产物路径。侧栏切换任务。这是工作台，不是单次聊天。

**第 6 周：Skill 目录**  
每个 Skill 一个文件夹：`SKILL.md`（给模型看的说明书）+ 可选脚本。用户点「周报」就把说明书塞进系统提示。还没有商店，本地文件夹就够。

**第 7 周：一个连接器**  
先做「只读」：例如用 IMAP 读最近 10 封邮件主题，或读一个 Notion 数据库。OAuth 很难，最小可用是「用户自己贴 API Token」。MCP 可以更晚。

**第 8 周以后才考虑**  
多 Agent 并行、微信遥控、云沙箱、技能市场、计费。远程执行等于把「改你家文件」的权限暴露到手机，安全设计必须先于功能。

## 7. 你不能省略的硬决定

- **默认工作目录**：办公 Agent 最容易把桌面扫成一团糟。只读写授权路径和产物盒。  
- **交作业 vs 只建议**：产品承诺是文件。UI 必须突出产物，而不是长聊天。  
- **本机执行 vs 云沙箱**：碰本地文件就要本机；怕泄密或电脑没开就用云端，但云端看不到你家硬盘。  
- **格式策略**：模型擅长文本；Office 二进制交给转换器/API。不要让模型「生成 xlsx 的 base64」。  
- **人还要不要看一眼**：删邮件、覆盖原表，必须批准；写新文件到产物盒可以松一些。

## 8. 和 MacBuddy

MacBuddy 的 **Work 引擎** 和 WorkBuddy 是近亲：热键唤出、干活、给结果。差别是 MacBuddy 走 **Mac 原生薄壳**（菜单栏、Finder、辅助功能），不要去复刻腾讯文档生态、技能商店、微信遥控。

该学的：任务有状态、产物是一等公民、工具按「办公对象」（文件/表）而不是按「代码对象」来设计。  
不该学的：做成办公套件，或和网盘抢「全家桶」。
