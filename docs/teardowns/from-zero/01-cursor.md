# Cursor：从零讲明白

## 1. 它到底是什么

Cursor 是一个**写代码用的编辑器**，看起来很像 VS Code（微软那个免费编辑器）。差别是：AI 不是旁边挂的插件，而是长在编辑器骨头里。

你可以把它想成：

- 普通编辑器 = 打字机  
- GitHub Copilot 插件 = 打字机旁边站了个会接话的人，但打字机本身改不了  
- Cursor = 把打字机拆开，把「猜下一句、改一整段、自己去翻仓库」焊进齿轮里  

所以它的开发思路第一句就是：**不要做插件，要 fork（复制一份）VS Code 源码再改。**

## 2. 它想解决什么问题

程序员最痛的不是「不会问 ChatGPT」，而是：

- 补全要在 **200 毫秒内** 出现，否则打字被打断  
- 改一个功能往往要动 **好几个文件**  
- 仓库有几万个文件，模型一次读不完，必须先 **检索**  
- 改完要能 **看 diff、能撤销**，不能黑箱覆盖磁盘  

Cursor 的产品句是：让你在熟悉的编辑器里，每一毫秒都被 AI 托着走。

## 3. 设计概念（厨房比喻）

把一次「帮我改登录」想成做菜：

| 概念 | 白话 | Cursor 里是什么 |
|---|---|---|
| 菜单 | 你点的菜 | 聊天 / Composer / Agent 里你输入的任务 |
| 冰箱 | 家里有什么食材 | 整个代码仓库 |
| 索引卡片 | 冰箱门上的目录，不用把冰箱搬出来 | Merkle 树 + 向量索引（语义搜索） |
| 主厨 | 会想、会下单的人 | 大模型 |
| 后厨工具 | 刀、灶、计时器 | 读文件、改文件、搜索、跑终端、MCP 外接工具 |
| 传菜口 | 给你看、让你尝一口再上桌 | 行内补全、diff 预览、点接受才写入 |

**Merkle 树（默克尔树）** 用老奶奶的话说：每个文件做一次「指纹」（哈希）。文件夹的指纹 = 里面所有东西的指纹合在一起。只要最顶上那个总指纹没变，就说明整个仓库没变。有文件改了，只从改的那条枝往上更新。这样不用每次把整个仓库重新扫描。

**向量索引** 用老奶奶的话说：不只按文件名搜「login」，而是把「这段代码大概在讲什么」变成一串数字。你问「登录逻辑在哪」，就拿这串数字去找最像的几段塞给模型。

**ReAct 循环**：想一下 → 动手（调用工具）→ 看结果 → 再想。不是一次生成全部答案。

## 4. 系统拆成哪些积木

从外到内：

1. **壳：VS Code 叉**  
   窗口、标签、扩展、终端、Git 面板都来自 VS Code。你们改的是：补全怎么画幽灵字、多文件 diff 怎么叠在编辑器上。

2. **四种快慢不同的 AI**（很重要，不要做成一个按钮）  
   - **Tab**：猜下一两个词/下一行，必须极快，常用小模型  
   - **行内修改（Cmd+K 一类）**：选中一段，改这一段  
   - **Composer / Agent**：多文件、会跑命令、会循环  
   - **Cloud Agent**：循环跑到云端虚拟机，笔记本合盖也能干  

3. **上下文引擎**  
   打开的文件、光标位置、最近编辑、lint 报错、@文件/@仓库检索结果、Rules（项目里的规定）。有人公开过「按优先级裁剪提示词」的思路：上下文太长就丢掉不重要的块。

4. **工具层**  
   读、搜、改、终端、MCP（一种「外接工具插座」标准）。工具在**你的电脑**上执行，模型只负责说「请调用」。

5. **云端**  
   索引同步、补全模型、账号。可以开隐私模式少上传代码。

## 5. 一次 Agent 任务怎么走（流程）

```
你输入「给登录加测试」
    → 程序收集：当前文件、规则、用语义搜索找到的相关测试文件
    → 发给模型（带工具清单）
    → 模型说：先 Read xxx.test.ts
    → 程序读盘，把内容当「观察」塞回去
    → 模型说：ApplyPatch 某某处
    → 编辑器显示 diff，你点接受（或 Agent 模式按策略自动应用）
    → 模型说：跑 npm test
    → 终端输出再喂回去
    → 红了就再改，直到模型认为完成或你点停
```

停下来的条件必须写死：最多步数、你点取消、测试通过、模型输出「没有工具了只有最终说明」。

## 6. 从零开发：按周做，不要第一周 fork VS Code

诚实说：完整 Cursor 需要编辑器团队 + 模型训练 + 向量库。你从零能做的是**同思路的最小产品**。

**第 0 周：只有聊天**  
一个窗口，把用户话发给任意 OpenAI 兼容接口，流式显示。没有工具。你会得到「会说话的记事本」。

**第 1 周：一个工具 ReadFile**  
模型若返回 JSON 或 XML 说要读路径，你的程序去读，再把内容发回。系统提示词里写清楚：你有且仅有 ReadFile。这是 Agent 的第一口奶。

**第 2 周：ApplyPatch**  
只允许 unified diff，应用前弹窗预览。**禁止**模型直接覆盖整个文件（容易把仓库写坏）。

**第 3 周：Grep / 列目录**  
还没有向量库。用本地 ripgrep 就够中小仓库。

**第 4 周：终端（只读命令白名单）**  
先只允许 `git status`、`git diff`、测试命令。有超时。这是安全分水岭。

**第 5 周：索引（可选）**  
对每个文件做哈希；改了再重新切块。切块按函数边界比按每 500 行傻切更好。向量库可以很晚再上，先用关键词搜。

**第 6 周以后才考虑**  
fork VS Code、Tab 补全、云端 Agent。Tab 是另一个产品（延迟极低的小模型），不要和 Agent 共用一个慢模型。

## 7. 你不能省略的硬决定

- 改文件前要不要人看 diff？（Cursor 偏向能看）  
- 索引放本地还是上传 embedding？  
- 工具失败时把报错原文喂回模型，让它自己修，不要静默吞掉  
- 主线程（编辑器界面）绝不能等模型；一切后台  

## 8. 和 MacBuddy

MacBuddy 已有「补丁预览再应用」和 sidecar，这是 Cursor Agent 里最值钱的那一段的缩小版。不要去造 Tab 和整套 IDE。把「热键秒开 + 补丁预览」做好，比模仿 Cursor 窗口更有特色。
