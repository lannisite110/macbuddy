## 1. 调查目的

回答四个问题：

1. Cursor、Codex、WorkBuddy、Qoder、DeepSeek Harness、Unsloth **各自解决什么痛点**？

4. 对 MacBuddy（Mac 原生菜单栏双核助手） **该学什么、不该抄什么**？

## 3. 核心发现摘要

### 3.1 同一口锅（Agent 循环）

除 Unsloth 外，其余产品内核都是：

**人说话 → 组装上下文 → 模型决策 → 调用工具 → 观察结果 → 再决策**，直到完成或等人批准。

差别主要在：外壳（IDE / CLI / 桌面工作台 / 插件树）、工具危险度、上下文从哪来（索引 / Wiki / 资料库 / 会话日志）。

### 3.2 两类完全不同的问题

| 类型 | 代表 | 问题 |
|---|---|---|
| **Harness / 产品壳** | Cursor、Codex、WorkBuddy、Qoder、dsh | 怎么让模型安全地干活并交付 |
| **模型运行时** | Unsloth | 怎么让权重在你机器上训得动、跑得动 |

把 Unsloth 当「又一个 Agent」会调研跑偏。

### 3.3 对 MacBuddy 的总判断

- **哲学**：薄壳 + sidecar（像 Codex / dsh）  
- **形态**：缩小的 Work（办公）+ 缩小的 Cursor（补丁预览）  
- **不要**：整套 IDE、腾讯办公全家桶、Repo Wiki 工厂、自研训练内核

## 4. 分产品调查结论

### 4.1 Cursor

- **是什么：** fork VS Code，AI 长在编辑器骨头里，而非插件。  
- **痛点：** 毫秒级补全、多文件修改、仓库检索、可审 diff。  
- **关键概念：** Merkle 增量索引、向量检索、ReAct；Tab / 行内 / Composer / Cloud Agent 必须分快慢。  
- **从零：** 先聊天 → ReadFile → ApplyPatch（必预览）→ Grep → 白名单终端；很晚才考虑 fork VS Code 与 Tab。  
- **MacBuddy：** 学补丁预览；不造 Tab 与整 IDE。

### 4.2 OpenAI Codex

- **是什么：** Rust 核心 Agent 发动机；CLI / TUI / IDE / Mac 都是客户端。  
- **痛点：** 多 UI 不要复制循环；要批准、取消、沙箱、CI 无界面。  
- **关键概念：** Thread / Turn / Item；App Server + JSON-RPC 双向（可反向问批准）；worktree 并行。  
- **从零：** while 循环 → 子进程打 JSON 事件 → 批准 / 取消 → jsonl 落盘 → 路径白名单。  
- **MacBuddy：** 事件协议写清（token / tool / approval / done）；View 里不写状态机。

### 4.3 WorkBuddy（腾讯）

- **是什么：** AI 办公工作台；交付物是 Word/Excel/PPT，不是 git commit。  
- **痛点：** 跨微信/邮箱/文档跳；聊天只给建议不交作业；外出遥控电脑。  
- **关键概念：** 资料库、Skill、连接器/MCP、产物篮、云沙箱 vs 本机。  
- **从零：** 聊天 → 授权目录只读 → 产物盒写入 → 表格工具 → 一种办公格式 → 任务状态 → 本地 Skill；微信/云沙箱很晚。  
- **MacBuddy：** 任务有状态、产物一等公民；不抄文档生态与微信遥控。

### 4.4 Qoder（阿里）

- **是什么：** Agent-first 编程平台（IDE + CLI）；口号：定目标，审结果。  
- **痛点：** 多文件任务、失忆、想委派整活。  
- **关键概念：** Agent / 工具 / 权限 / 上下文四齿轮；Quest；Repo Wiki / Memory；Plan/Goal/Workflow；权限 allow/ask/deny。  
- **从零：** 绑仓库聊天 → 只读工具 → 编辑+diff → 权限三态 → 任务状态机 → AGENTS.md → 测试白名单 → Wiki 雏形。  
- **MacBuddy：** Code 切片停在补丁+预览+可选 git；不做完整 IDE/专家团。

### 4.5 DeepSeek Harness（dsh）

- **是什么：** 开源 Agent 底盘（MIT，开发者预览）；**不是模型**。Cordis 负责插件装卸载。  
- **痛点：** 核心缠死难换；多外壳复制循环；无法回放「模型当时看见了什么」。  
- **关键概念：** 一切皆插件；profile/bundle/patch；Turn/Step；**会话日志=真相**（模型可见 ⇒ 可从日志重建）；能力缝（Seam）。  
- **从零：** jsonl 铁律 → 工具注册表 → 执行守卫 → 可替换 runTurn → 配置叠层 → UI 只订阅日志；不必第一周移植 Cordis。  
- **MacBuddy：** 只追加事件、sidecar 可替换、协议可序列化；不移植 Cordis。

### 4.6 Unsloth

- **是什么：** NVIDIA 上加速 LoRA/QLoRA 训练；Desktop 帮本机跑/导出模型。Mac 上多走 llama.cpp Metal / MLX。  
- **痛点：** 模型太大、全量微调太贵、格式分裂（训练权重 vs GGUF/MLX）。  
- **关键概念：** 量化、LoRA/QLoRA、Triton 融合内核（NVIDIA）；Mac 是另一条河。  
- **从零：** MacBuddy 用户优先第 0 层——Ollama/Desktop 当 `/v1` 供应商；认真 QLoRA 用 NVIDIA。  
- **MacBuddy：** 对接 OpenAI 兼容接口即可；16GB 优先 ≤4B Q4；不自研训练框架。

## 5. 横向对比

| 维度 | Cursor | Codex | WorkBuddy | Qoder | dsh | Unsloth |
|---|---|---|---|---|---|---|
| 主战场 | IDE 编码 | Agent 核心 | 办公交付 | 编程委派 | 可插拔底盘 | 训练/推理 |
| 交付物 | 代码 diff | 事件流/补丁 | 文档表格 | Quest+diff | 会话日志 | 权重/GGUF |
| 外壳 | VS Code 叉 | 多客户端 | 桌面+IM | IDE+CLI | Web/Headless | Desktop/库 |
| 开源核心 | 否（产品） | 部分公开形态 | 否 | 否 | 是（预览） | 是（库/应用） |
| 与 Agent 循环 | 完整 | 完整 | 完整 | 完整 | 完整且可换 | 无 |

**共性硬决定（Agent 类）：**  
改盘前是否给人看；工具失败是否原文回灌；界面线程不阻塞模型；工作区/白名单边界。

---

## 6. 对 MacBuddy 的行动建议

1. **保持** 薄壳（SwiftUI）+ sidecar；事件：token / tool / approval / done / error。  
2. **Work 侧** 学任务状态与产物盒，不做网盘/技能市场。  
3. **Code 侧** 学补丁预览与权限三态，不做 Quest IDE / Wiki 工厂。  
4. **模型侧** 接本地 Ollama/Unsloth Desktop `/v1`；小模型保体感。  
5. **预期管理** 「从零」= 同类最小系统，不是复刻任一完整商业 IDE。

---

## 7. 结论

六份 Agent/产品拆解证明：**值钱的是「循环 + 工具守卫 + 可审交付 + 可回放上下文」**，不是聊天窗口皮肤。  
Unsloth 证明：**模型怎么跑** 与 **Agent 怎么干** 应解耦——MacBuddy 只消费 OpenAI 兼容接口即可。
