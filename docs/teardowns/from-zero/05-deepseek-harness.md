# DeepSeek Harness（dsh）：从零讲明白

## 1. 它到底是什么

DeepSeek Harness（命令一般叫 `dsh`）**不是新模型**。  
DeepSeek 的模型负责「想和下一步」；Harness 负责「给模型工位、工具、权限、以及这次干活的记忆」。

2026 年 8 月 DeepSeek AI 开源（MIT，开发者预览，接口还会破）。口号是：**Everything is a plugin.（一切皆插件。）**

底下还有一层叫 **Cordis**：只负责把插件装上、卸下、理清依赖。卸插件时，它注册过的工具、监听、配置会一起撤掉，不留幽灵。

三者千万分清：

| 名字 | 干什么 | 不干什么 |
|---|---|---|
| **模型** | 吐字、决定调哪个工具 | 自己打不开文件、记不住上次（除非你把历史喂回去） |
| **Harness（dsh）** | 工位、工具表、沙箱、会话日志、循环 | 不训练、不托管权重 |
| **Cordis** | 插拔插件的内核 | 不是 Agent 专用，dsh 碰巧建在它上面 |

另有一个社区 Python 包也叫 deepseek-harness，是 V4 API 客户端，**和这个官方 TypeScript 项目无关**。本文只讲官方：`npx @deepseek-ai/dsh web`，本地网页一般在 `http://127.0.0.1:3080`。需要 Node 22.x 或 24+。

## 2. 它想解决什么问题

做 Agent 的人会痛：

- 循环、工具、存档、UI 缠在一个「核心」里，想换沙箱或换模型就要改核心、容易改炸  
- 换一个产品外壳（网页、无界面脚本）又把循环复制一遍  
- 出了问题无法回放：模型当时究竟看见了什么？  

dsh 的开发思路：

1. **没有神圣不可改的核心**：连「Agent 循环本身」也是插件，不喜欢就换一个  
2. **用配置叠出来**：profile（档案）+ bundle（插件包）+ patch（补丁配置）  
3. **模型看见的，必须能从日志重建** —— 这是铁律  

你可以把它想成：Codex 把发动机做成 Rust 核心 + JSON-RPC；dsh 把发动机拆成可热插拔的插件树。哲学相近，组合方式更「乐高」。

## 3. 设计概念（厨房可换灶台）

### 插件树

启动时不是「运行一个大程序」，而是按顺序往空清单上叠：

1. 档案里列出的 **bundle**（例如 `dsh-base` 先上：模型适配、工具、存储、沙箱、批准、设置）  
2. 网页档案再叠 `dsh-web-app`；无界面档案叠 `dsh-headless`  
3. 该档案自己的 `cordis.patch.yml`  
4. 整机 home 里的补丁  
5. 命令行 `--patch`  

后写的覆盖先写的（按行 id 整段替换，不是深度合并）。想看你机器真正启动了啥：`dsh --profile web --dump-config`。

### 服务 / 事件 / 可撤销效果

插件往共享的 `ctx`（上下文对象）上挂服务，例如 `ctx.tools`、`ctx.llm`、`ctx.sessions`。  
插件之间主要靠 **打事件** 协作，而不是互相 import 死缠。  
注册工具、监听事件，都记成「效果」；插件卸载就反向撤销。所以能热替换：改插件源码 → 卸旧 → 装新 → 不留旧监听。

### Turn 和 Step（回合和一步）

用打电话：

- **Step（一步）**：问模型一次 + 它这次点名的工具都跑完  
- **Turn（一回合）**：从你这句话被接住，到暂时不欠下一问模型。里面可以有 0 步或多步  

官方骨架（简化成老奶奶能跟着走的顺序）：

```
回合开始
  拿出下一批输入（你的话，或工具后还要再问模型）
  拼系统提示各段落 + 当前工具清单
  若这一拍被插件直接拒绝 → 回合结束，日志仍记下「试过」
  否则：一步开始
      把输入写成日志里的用户消息
      从日志投影出「模型该看见的历史」
      流式调用模型
      若有工具：执行前检查 → 执行 → 执行后钩子 → 工具结果写入日志
      一步结束
      若还欠再问模型，或又来了新输入 → 再一步
  回合结束
```

### 会话日志 = 真相

日志是 **只追加** 的事件流（谁说了什么、模型吐了哪些块、调了什么工具）。  
界面重放、分叉会话、恢复中断，都从这条流投影出来。  
铁律：**凡是进了模型请求的内容，都必须能从日志重建。** 想给模型看新东西，先定义一种新的会话事件，再从日志渲染。不要偷偷在内存里塞一段只有这次进程知道的话。

### 能力缝（Seam）

一种能力拆成三角：

- **定义**：接口长什么样（比如「文件系统」）  
- **提供者**：本地磁盘，或远程沙箱  
- **消费者**：Bash、读文件工具、LSP……它们只认接口  

所以你把文件系统 + 子进程一齐指向远程沙箱，Bash / 终端 / 语言服务会跟着走，不用每种工具改一遍。这是「换灶台，锅铲不用重买」。

### 运行模式（可以想成不同的厨师规矩）

公开资料和社区说明里常见：

- **标准**：普通工具调用（模型说「调 xxx」，程序去调）  
- **PTC（Programmatic Tool Calling）**：模型写 TypeScript，程序跑这段代码来调工具。适合要组合很多工具、像写小程序一样编排的情况  
- **最小（minimal）**：几乎只留 Bash + 改文件编辑器，评测时表面干净、可复现  
- **create**：方便实验新插件  

评测数字往往跑在最小模式上，和带一堆插件的网页日常不是同一套工具表。

## 4. 系统拆成哪些积木（核心包在干什么）

公开架构里这些包都挂在 Cordis 树上：

| 包 | 白话 | 挂在 |
|---|---|---|
| session | 只追加的事件日志 + 内存里的会话 | `ctx.sessions` |
| system-prompt | 把各插件贡献的提示段落和工具 schema 拼起来 | `ctx.systemPrompt` |
| tools | 工具注册表 + 带守卫的执行管道 | `ctx.tools` |
| agent | Agent 接口、名册、`agent/*` 事件 | `ctx.agents` |
| agent-loop | 默认司机：真正推进 turn/step 的那一段 | `ctx.agentLoop` |
| llm | 消息/流式的词汇 + 适配器插口 | `ctx.llm` |

扩展时优先 **加插件、听事件**，而不是去改 loop。例如：加模型 = 在 `ctx.llm` 注册适配器；加能力 = 注册工具（schema 会自动进提示词）；拦截一次调用 = 听 `tools/pre-execute`。

网页 UI 也是 bundle。换皮肤、换编辑器集成，按设计是叠插件，而不是 fork 整棵树。开发者预览阶段兼容性会破，不要当成已经冻住的生产内核。

安全注意：本地 Web UI 按设计绑在本机；文档说明拒绝把 `--host` 开到 `0.0.0.0` 当公网服务。那是故意的：Agent 能碰文件，不能当网站裸奔。

## 5. 一次请求怎么走（和你在浏览器里点发送）

```
dsh web 启动 → 按 web 档案装插件树 → 本机 3080 打开界面
你选工作区、选模型、输入任务
    → 往 Agent 收件箱塞一条消息
    → loop 开启 turn，投影日志，拼提示词和工具
    → 适配器流式打模型，界面画 chunk
    → 工具经守卫执行，结果 append 进日志
    → 需要再想就再 step；完毕 turn/end
刷新页面：只重放日志，不靠「当时内存里还有什么」
```

无界面：`headless` 档案，一次性跑完退出，给脚本用。循环插件仍是那一个（或你换成自己的）。

## 6. 从零开发：先抄铁律，不要先抄 Cordis

在自己项目里「做出 dsh 那种形状」，不必第一周重写 Cordis。

**第 0 周：一个 while 循环 + jsonl**  
每次模型输入输出、每次工具调用，都 `append` 一行 JSON 到 `session.jsonl`。下次启动只从文件重建 `messages`。禁止有「只存在于变量里、不写日志」的系统提示补丁。这就是最小铁律。

**第 1 周：工具注册表**  
`tools = { name: { schema, handler } }`。提示词里的工具列表从这张表生成。加工具 = 注册，不改循环。这是「插件」的心理模型，还不用框架。

**第 2 周：执行守卫**  
`pre-execute`：路径在工作区内？命令在白名单？要不要问人？通过才跑 handler。这是沙箱的门卫，不是虚拟机。

**第 3 周：把循环变成可替换函数**  
`runTurn(ctx)` 单独一个模块。将来可以换成「PTC：先让模型写脚本再执行」。主程序只调用 `runTurn`。

**第 4 周：配置叠层**  
`base.yaml` + `user.yaml` 覆盖。用户能换模型基址、能关某工具。这是简陋 profile，还不是 Cordis。

**第 5 周：UI 只订阅日志**  
终端或网页只读 jsonl / 事件流画画。不要在 React/SwiftUI 里另存一份「模型看过的话」。

**第 6 周以后**  
真要生态，再引入插件加载器（动态 import + 卸载时去掉监听）。Cordis 的价值是依赖和可撤销效果；在只有三个插件时，手写就够。

若你是 **用** dsh 而不是再造：装 Node → `npx @deepseek-ai/dsh web` → 配自己的 OpenAI 兼容接口 → 用 `--dump-config` 看树 → 写一个最小插件（一个工具）挂到 profile。创建插件前读他们的 development 文档；预览期会破兼容。

## 7. 你不能省略的硬决定

- **日志是宪法**：破坏「模型可见 ⇒ 可重建」，分叉和回放会撒谎。  
- **循环可替换**：把策略写死在 UI 里，就失去 dsh 的意义。  
- **本机绑定**：能改磁盘的 Agent 不要暴露到局域网，除非你另做认证和沙箱。  
- **最小工具面 vs 日常插件堆**：评测和日常可以是两个 profile，不要混成一个说不清的工具表。  
- **PTC 的安全**：执行模型生成的 TypeScript 等于执行未知代码，必须沙箱，比「调一个 JSON 工具」更危险。

## 8. 和 MacBuddy

MacBuddy 已经是薄壳 + sidecar。向 dsh 学三件事即可：

1. 会话事件只追加，SwiftUI 只投影  
2. 工具和模型适配放在 sidecar 里可替换，不要写进 View  
3. 给模型看的每一段话都来自可序列化的日志/协议，不要在 App 里偷偷拼  

不必在 Swift 里移植 Cordis。哲学对齐，实现继续用你们的 Unix socket 协议。
